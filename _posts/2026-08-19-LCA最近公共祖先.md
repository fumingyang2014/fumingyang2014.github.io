# LCA 完整教学

## 什么是 LCA

先建立直觉：在一棵有根树上，两个节点的「最近公共祖先」到底指什么。

### 📖 正式定义

**LOWEST COMMON ANCESTOR**

#### 最近公共祖先

在根为 1 的树上，对任意两个节点 u 与 v：它们所有公共祖先中，深度最大的那一个，记作 LCA(u, v)。

**WHY IT MATTERS**

#### 为什么重要

树上两点距离、路径最值、树上差分、次小生成树等问题都会用到 LCA，它是竞赛里的常用基础工具。

> 💡 公共祖先 = 既是 u 的祖先、又是 v 的祖先的节点。根节点一定是任意两点的公共祖先，所以公共祖先永远存在；最近公共祖先就是其中深度最深的。

### 🔍 三种关键场景（边界情况）

#### ① u 是 v 的祖先

比如 u 在 v 到根的路径上：则 LCA(u, v) = u。这是查询里最常见的边界，倍增算法会在深度对齐后直接判断 u == v 来收尾。

#### ② u == v

同一个节点：LCA(u, u) = u。算法天然成立（深度差为 0，直接判等返回）。

#### ③ 根节点参与

任何节点与根：LCA(u, root) = root。根的深度是 0，往上没有祖先。

### 📚 术语表

| 术语 | 英文 | 含义 |
|------|------|------|
| 根节点 | Root | 树的起点，深度为 0，没有父节点 |
| 深度 | Depth | 节点到根经过的边数（根 = 0） |
| 父节点 | Parent / fa | 树上相邻的上一层节点 |
| 祖先 | Ancestor | 从父节点一直沿边走到根，途中的一切节点（含自己） |
| 后代 | Descendant | 子树内的一切节点（含自己） |
| 子树 | Subtree | 以某节点为根的子结构 |
| 叶子 | Leaf | 没有子节点的节点 |
| 最近公共祖先 | LCA | Lowest Common Ancestor，两节点的最深公共祖先 |

> ⚠️ 常犯错误：祖先包含自己。所以 LCA(u, v) 可以等于 u、等于 v，甚至等于根。做题时先想清楚「u 是否在 v 的祖先链上」。

## 基础准备：存储 · 深度 · 父节点

任何 LCA 算法都需要两个前置信息：每个节点的深度和父节点。

### 🧱 树的两种存法

#### ① 父指针数组 fa[N]

只记录每个节点的父是谁。适合查询多于建树、结构简单的情况，倍增的 up 表就是基于它扩展的。缺点：无法遍历子树。

#### ② 邻接表 vector<int> g[N]

记录每个节点的所有邻居。可以 DFS/BFS 遍历全树，求出深度和父节点。竞赛中最常用。

### 🧭 深度 & 父节点的求法（BFS）

规则就一条：子节点的深度 = 父节点深度 + 1。从根出发逐层向下「扩散」，用队列保证先处理的都是更浅的节点。

🧠 伪代码
```
BFS 求深度 & 父节点:
  queue = [1]; depth[1] = 0
  while queue 非空:
    u = 出队(queue)
    for v ∈ children(u):
      depth[v] = depth[u] + 1
      fa[v] = u; 入队(queue, v)
```

> ✅ BFS / DFS 都能求深度：BFS 用队列逐层扩散，DFS 用递归一路到底再回溯。倍增预处理里我们演示 BFS 版本，因为它的遍历顺序在动画里更清晰。

## 朴素 LCA：一步一步爬

思路很直接：① 深度对齐，深的节点一层层往上爬，直到两节点同深度；② 同步上爬，两个节点一起向上爬，直到相遇。相遇点就是 LCA。

> ⚠️ 朴素算法每次查询最坏要爬 O(n) 层（比如一条链上查询最深与最深）。倍增要优化的就是这个：把一次爬一层，改成一次跳 2^k 层。

🧠 算法伪代码
```
预处理 dfs(u, d):
  depth[u] = d
  for v ∈ children(u): dfs(v, d+1)
查询 lca(u, v):
  while depth[u] > depth[v]: u = fa[u] // 对齐
  while depth[v] > depth[u]: v = fa[v]
  while u ≠ v: u = fa[u]; v = fa[v] // 同步爬
  return u
```

### 🧠 朴素算法的局限

> 🚨 在一条链的树上，查询两个最深节点：u 要爬 depth[u] - depth[lca] 层，v 同样。深度是 n 时，单次查询就是 O(n)。n = 10⁵ 时这个复杂度没法用，下一章开始优化。

---

## 倍增原理：一次跳 2^k 层

朴素算法慢在「一次只能爬一层」。倍增的思路是：预处理一张「任意节点向上跳 2^k 层」的表，查询时用二进制分解把深度差拆成几个 2^k 之和，每次跳跃都是 O(1)。

### ① 任意整数都能拆成若干个 2 的幂之和

任意正整数都能写成若干个 2^k 的和（这正是它的二进制表示）。所以「向上爬任意层」都可以拆成「跳几次 2^k 层」。

> 💡 6 = 4 + 2（二进制 110）→ 先跳 2²=4 层，再跳 2¹=2 层，两步完成！如果朴素地爬，要爬 6 层。跳跃次数最多不超过 ⌈log₂(n)⌉ 次。

### ② 台阶跳跃

跳 2⁰=1 层 | 跳 2¹=2 层 | 跳 2²=4 层 | 跳 2³=8 层

### 🧬 up 表：up[u][k] 是什么

#### 定义

up[u][k] = 从节点 u 向上跳 2^k 层到达的节点编号。
例如 up[16][1]：16 向上跳 2 层 → 16 → 14 → 10，所以 up[16][1] = 10。跳到根之上记为 0。

#### 递推公式（核心）

up[u][k] = up[ up[u][k-1] ][k-1]

跳 2^k 层 = 先跳 2^(k-1) 层到中点，再跳 2^(k-1) 层。两个半程拼成一个全程，倍增的名字也由此而来。

> ✅ 递推公式之所以成立：先跳到 up[u][k-1]（走了 2^(k-1) 层），再从那里跳 2^(k-1) 层。总共正好是 2^(k-1) + 2^(k-1) = 2^k 层。

### 🤔 为什么查询时要从大到小试探？

> ⚠️ 倍增查询的「一起跳」阶段，规则是：up[u][k] ≠ up[v][k] 才跳。为什么不能相等就跳？因为若 up[u][k] == up[v][k]，这个公共祖先可能就是 LCA，也可能在 LCA 之上。跳过去就可能越过答案，所以宁可不跳，最后用 up[u][0] 一步到位。这就是「试探」的意思。

## 倍增预处理：BFS + up 表逐格构建

预处理做两件事：① BFS 求出每个节点的深度和父节点（up[u][0]）；② 用递推公式逐列填满 up 表。总复杂度 O(n log n)。

🧠 算法伪代码
```
预处理 bfs(u):
  depth[u] = depth[fa[u]] + 1 // ① 深度
  up[u][0] = fa[u] // ② 第一列
  for j = 1 .. LOG-1: // ③ 逐列递推
    up[u][j] = up[ up[u][j-1] ][j-1]
查询 lca(u, v):
  if depth[u] < depth[v]: swap(u, v)
  for j = LOG-1 .. 0: // ④ 对齐（二进制）
    if depth[u] - 2^j ≥ depth[v]: u = up[u][j]
  if u == v: return u
  for j = LOG-1 .. 0: // ⑤ 一起试探
    if up[u][j] ≠ up[v][j]: u = up[u][j]; v = up[v][j]
  return up[u][0]
```

#### 🗂️ up[u][j] 倍增表示例

| 节点 i | up[i][0] 2^0 层 | up[i][1] 2^1 层 | up[i][2] 2^2 层 | up[i][3] 2^3 层 |
|--------|-----------------|-----------------|-----------------|-----------------|
| 1 | 0 | 0 | 0 | 0 |
| 2 | 1 | 0 | 0 | 0 |
| 3 | 1 | 0 | 0 | 0 |
| 4 | 2 | 1 | 0 | 0 |
| 5 | 3 | 1 | 0 | 0 |
| 6 | 4 | 2 | 0 | 0 |
| 7 | 4 | 2 | 0 | 0 |
| 8 | 5 | 3 | 0 | 0 |
| 9 | 5 | 3 | 0 | 0 |
| 10 | 6 | 4 | 1 | 0 |
| 11 | 7 | 4 | 1 | 0 |
| 12 | 8 | 5 | 1 | 0 |
| 13 | 8 | 5 | 1 | 0 |
| 14 | 10 | 6 | 2 | 0 |
| 15 | 10 | 6 | 2 | 0 |
| 16 | 14 | 10 | 4 | 0 |
| 17 | 14 | 10 | 4 | 0 |

> 💡 第一列是 BFS 顺带填的，后面的列才是递推公式发挥作用的地方。填完整张表只需要 O(n log n) 次计算。

## 倍增查询：二进制对齐 + 试探跳跃

查询分三步：① 保证 u 更深（不够就 swap）；② 深度对齐，用二进制分解把 u 跳到与 v 同深；③ 一起试探，从大到小尝试 2^k 层，up 值不同才跳；最后 up[u][0] 一步到 LCA。

🧠 算法伪代码
```
查询 lca(u, v):
  if depth[u] < depth[v]: swap(u, v) // 保证 u 更深
  d = depth[u] - depth[v] // 深度差
  for j = LOG-1 .. 0: // ④ 深度对齐（二进制）
    if (d >> j) & 1: u = up[u][j]
  if u == v: return u
  for j = LOG-1 .. 0: // ⑤ 一起试探跳跃
    if up[u][j] ≠ up[v][j]:
      u = up[u][j]; v = up[v][j]
  return up[u][0] // 一步到 LCA
```

### 🎯 边界案例

> 🎯 「祖先后代」：u 在 v 的祖先链上 → 深度对齐后 u == v，直接返回；「u == v」：深度差 0，零次跳跃；「同父兄弟」：一起跳阶段几乎全跳过，最后 up[u][0] 一步到位。都是高频边界，务必跑一遍。

## 复杂度分析：差距有多大？

n = 100,000 时：朴素最坏爬 100,000 层，倍增只需 ⌈log₂n⌉ = 17 跳。若查询次数 q = n：朴素总操作 ≈ 10,000,000,000，倍增 ≈ 1,700,000，快了约 5882×。

#### ⚖️ 全维度对比

| 维度 | 🧗 朴素 | 🚀 倍增 |
|------|---------|---------|
| 预处理 | 求深度（BFS/DFS） | 求深度 + 构建 up 表 |
| 预处理时间 | O(n) | O(n log n) |
| 预处理空间 | O(n) | O(n log n) |
| 单次查询 | O(n) | O(log n) |
| 代码难度 | ★☆☆☆☆ | ★★☆☆☆ |
| 适用场景 | 小树 / 教学理解 | 竞赛通用（n ≤ 10⁵ 量级） |

> ✅ 结论：预处理多花一点点（O(n log n) 的一次性投入），换来每次查询从 O(n) 降到 O(log n)。当查询次数 q 很大时，总复杂度从 O(nq) 变成 O(n log n + q log n)，差距会非常大。

## C++ 代码实现（模板）

完整可用的倍增 LCA 模板。直接复制即可在 OJ 上使用。

**lca.cpp · 倍增 LCA 模板**
```cpp
#include <bits/stdc++.h>
using namespace std;
const int N = 500010, LOG = 20;        // 2^20 > 1e5，LOG = ceil(log2 N)+1
vector<int> g[N];                       // 邻接表存树
int depth[N], up[N][LOG];               // 深度 & 倍增表
void dfs(int u, int fa) {               // 预处理：求深度 + 填 up 表
    up[u][0] = fa;                      // 跳 2^0=1 层 = 父节点
    for (int j = 1; j < LOG; j++)
        up[u][j] = up[up[u][j-1]][j-1]; // 倍增递推：两个半程拼全程
    for (int v : g[u]) if (v != fa) {
        depth[v] = depth[u] + 1;        // 子节点深度 = 父 + 1
        dfs(v, u);
    }
}
int lca(int u, int v) {
    if (depth[u] < depth[v]) swap(u, v);// 保证 u 更深
    int d = depth[u] - depth[v];        // 深度差
    for (int j = LOG-1; j >= 0; j--)    // 深度对齐：二进制拆分
        if (d >> j & 1) u = up[u][j];
    if (u == v) return u;               // 边界：u 就是 v 的祖先
    for (int j = LOG-1; j >= 0; j--)    // 一起试探跳跃（从大到小）
        if (up[u][j] != up[v][j]) u = up[u][j], v = up[v][j];
    return up[u][0];                    // 一步跳到 LCA
}
int main() {
    int n, m, s; cin >> n >> m >> s;
    for (int i = 1; i < n; i++) { int x, y; cin >> x >> y;
        g[x].push_back(y); g[y].push_back(x); }
    depth[s] = 0; dfs(s, 0);
    while (m--) { int u, v; cin >> u >> v; cout << lca(u, v) << '\n'; }
    return 0;
}
```

> ⚠️ 三个易错点：① LOG 取 `ceil(log2(n)) + 1`（n=10⁵ 时约 17+1）；② 从根 DFS 时要传 fa=0，并跳过父节点防止死循环；③ 查询时先 swap 保证 u 更深，再枚举二进制位。

### 🚀 变体：递归改 BFS 版

竞赛题经常「卡递归栈」（n = 10⁶ 的链会爆栈），此时改用 BFS/显式栈预处理。核心只有一句话：`up[u][j] = up[up[u][j-1]][j-1]` 与遍历顺序无关，先求出 depth 和 up[u][0] 即可。

**lca_bfs.cpp · 防爆栈版本**
```cpp
#include <bits/stdc++.h>
using namespace std;
const int N = 1000010, LOG = 21;
vector<int> g[N];
int depth[N], up[N][LOG];
queue<int> q;
void bfs(int root) {                     // BFS 版预处理（防爆栈）
    q.push(root); depth[root] = 0; up[root][0] = 0;
    while (!q.empty()) {
        int u = q.front(); q.pop();
        for (int j = 1; j < LOG; j++)
            up[u][j] = up[up[u][j-1]][j-1];   // 同一行递推
        for (int v : g[u]) if (v != up[u][0]) {
            depth[v] = depth[u] + 1;
            up[v][0] = u;
            q.push(v);
        }
    }
}
// lca 函数与 DFS 版完全相同，略
int main() { int n, m, s; cin >> n >> m >> s;
    /* 建图（略） */ bfs(s);
    while (m--) { int u, v; cin >> u >> v; cout << lca(u, v) << '\n'; }
    return 0;
}
```

## 应用与例题

LCA 是树上问题的地基。学会模板后，下面的经典应用都是「模板 + 一层推理」。

### 📐 应用一：树上两点距离

dist(u, v) = depth[u] + depth[v] − 2 × depth[ LCA(u, v) ]

> 💡 直觉：depth[u] + depth[v] 把两条到根的路径长度加起来了，其中 LCA 到根这段被重复计了两次，所以要减掉 2 × depth[LCA]。这是最常用的 LCA 应用（树上最短路径长度）。

### 🏔️ 应用二：树上路径最大值 / 最小值 / 边权和

把 up 表扩展成 mx[u][k]（从 u 向上 2^k 层路径上的最大值），递推时同步维护：`mx[u][k] = max(mx[u][k-1], mx[up[u][k-1]][k-1])`。查询 u→v 路径最值时，把路径拆成 u→LCA 和 v→LCA 两段，每段用二进制跳跃合并答案。「货车运输」等题就靠这个维护。

### 📝 例题精讲

**模板题 · 入门**

#### 【模板】最近公共祖先（LCA）

给定一棵 n 个节点的树（根为 1），q 次询问 LCA(u, v)。n, q ≤ 10⁵。

思路：直接套模板。注意本题 n 可达 10⁵，朴素 O(nq) 必 TLE（超时），正好用倍增来对比复杂度差距。

代码：使用上方模板，LOG 取 17（2¹⁷ = 131072 > 10⁵）。

**提高 · 货车运输类**

#### 树上路径最小边权 / 最大边权

n 个点的树，每条边有边权，q 次询问 u → v 路径上最小值。n, q ≤ 10⁵。

思路：维护 mn[u][k] = 从 u 向上 2^k 层路径上边权最小值。查询时把 u→v 路径拆成 u→lca、v→lca 两段，每一段从大到小跳并合并 mn 值。

递推：`mn[u][k] = min(mn[u][k-1], mn[up[u][k-1]][k-1])`。这就是「倍增 + 路径统计」的通用套路。

**经典 · 树上差分**

#### 路径加值 + 单点查询（树上差分）

给 u→v 路径上所有节点加 w，最后求每个点的值。n, q ≤ 10⁵。

思路：差分数组 cnt[]：`cnt[u]++, cnt[v]++, cnt[lca]--, cnt[fa[lca]]--`。全部操作后做一次树上前缀和（DFS 累加子树和），每个点的值就出来了。LCA 负责找到「分叉点」。

> 🎯 学习路径建议：先吃透「距离公式」的推导（纸笔画一遍），再做「路径最值」的 mn 表扩展，最后尝试树上差分。每一步都在复用倍增的「跳 2^k 合并信息」思想。

## 什么是 LCA

先建立直觉：在一棵有根树上，两个节点的「最近公共祖先」到底指什么。

### 📖 正式定义

**LOWEST COMMON ANCESTOR**

#### 最近公共祖先

在根为 1 的树上，对任意两个节点 u 与 v：它们所有公共祖先中，深度最大的那一个，记作 LCA(u, v)。

**WHY IT MATTERS**

#### 为什么重要

树上两点距离、路径最值、树上差分、次小生成树等问题都会用到 LCA，它是竞赛里的常用基础工具。

> 💡 公共祖先 = 既是 u 的祖先、又是 v 的祖先的节点。根节点一定是任意两点的公共祖先，所以公共祖先永远存在；最近公共祖先就是其中深度最深的。

### 🔍 三种关键场景（边界情况）

#### ① u 是 v 的祖先

比如 u 在 v 到根的路径上：则 LCA(u, v) = u。这是查询里最常见的边界，倍增算法会在深度对齐后直接判断 u == v 来收尾。

#### ② u == v

同一个节点：LCA(u, u) = u。算法天然成立（深度差为 0，直接判等返回）。

#### ③ 根节点参与

任何节点与根：LCA(u, root) = root。根的深度是 0，往上没有祖先。

### 📚 术语表

| 术语 | 英文 | 含义 |
|------|------|------|
| 根节点 | Root | 树的起点，深度为 0，没有父节点 |
| 深度 | Depth | 节点到根经过的边数（根 = 0） |
| 父节点 | Parent / fa | 树上相邻的上一层节点 |
| 祖先 | Ancestor | 从父节点一直沿边走到根，途中的一切节点（含自己） |
| 后代 | Descendant | 子树内的一切节点（含自己） |
| 子树 | Subtree | 以某节点为根的子结构 |
| 叶子 | Leaf | 没有子节点的节点 |
| 最近公共祖先 | LCA | Lowest Common Ancestor，两节点的最深公共祖先 |

> ⚠️ 常犯错误：祖先包含自己。所以 LCA(u, v) 可以等于 u、等于 v，甚至等于根。做题时先想清楚「u 是否在 v 的祖先链上」。

## 基础准备：存储 · 深度 · 父节点

任何 LCA 算法都需要两个前置信息：每个节点的深度和父节点。

### 🧱 树的两种存法

#### ① 父指针数组 fa[N]

只记录每个节点的父是谁。适合查询多于建树、结构简单的情况，倍增的 up 表就是基于它扩展的。缺点：无法遍历子树。

#### ② 邻接表 vector<int> g[N]

记录每个节点的所有邻居。可以 DFS/BFS 遍历全树，求出深度和父节点。竞赛中最常用。

### 🧭 深度 & 父节点的求法（BFS）

规则就一条：子节点的深度 = 父节点深度 + 1。从根出发逐层向下「扩散」，用队列保证先处理的都是更浅的节点。

🧠 伪代码
```
BFS 求深度 & 父节点:
  queue = [1]; depth[1] = 0
  while queue 非空:
    u = 出队(queue)
    for v ∈ children(u):
      depth[v] = depth[u] + 1
      fa[v] = u; 入队(queue, v)
```

> ✅ BFS / DFS 都能求深度：BFS 用队列逐层扩散，DFS 用递归一路到底再回溯。倍增预处理里我们演示 BFS 版本，因为它的遍历顺序在动画里更清晰。

## 朴素 LCA：一步一步爬

思路很直接：① 深度对齐，深的节点一层层往上爬，直到两节点同深度；② 同步上爬，两个节点一起向上爬，直到相遇。相遇点就是 LCA。

> ⚠️ 朴素算法每次查询最坏要爬 O(n) 层（比如一条链上查询最深与最深）。倍增要优化的就是这个：把一次爬一层，改成一次跳 2^k 层。

🧠 算法伪代码
```
预处理 dfs(u, d):
  depth[u] = d
  for v ∈ children(u): dfs(v, d+1)
查询 lca(u, v):
  while depth[u] > depth[v]: u = fa[u] // 对齐
  while depth[v] > depth[u]: v = fa[v]
  while u ≠ v: u = fa[u]; v = fa[v] // 同步爬
  return u
```

### 🧠 朴素算法的局限

> 🚨 在一条链的树上，查询两个最深节点：u 要爬 depth[u] - depth[lca] 层，v 同样。深度是 n 时，单次查询就是 O(n)。n = 10⁵ 时这个复杂度没法用，下一章开始优化。

---

## 倍增原理：一次跳 2^k 层

朴素算法慢在「一次只能爬一层」。倍增的思路是：预处理一张「任意节点向上跳 2^k 层」的表，查询时用二进制分解把深度差拆成几个 2^k 之和，每次跳跃都是 O(1)。

### ① 任意整数都能拆成若干个 2 的幂之和

任意正整数都能写成若干个 2^k 的和（这正是它的二进制表示）。所以「向上爬任意层」都可以拆成「跳几次 2^k 层」。

> 💡 6 = 4 + 2（二进制 110）→ 先跳 2²=4 层，再跳 2¹=2 层，两步完成！如果朴素地爬，要爬 6 层。跳跃次数最多不超过 ⌈log₂(n)⌉ 次。

### ② 台阶跳跃

跳 2⁰=1 层 | 跳 2¹=2 层 | 跳 2²=4 层 | 跳 2³=8 层

### 🧬 up 表：up[u][k] 是什么

#### 定义

up[u][k] = 从节点 u 向上跳 2^k 层到达的节点编号。
例如 up[16][1]：16 向上跳 2 层 → 16 → 14 → 10，所以 up[16][1] = 10。跳到根之上记为 0。

#### 递推公式（核心）

up[u][k] = up[ up[u][k-1] ][k-1]

跳 2^k 层 = 先跳 2^(k-1) 层到中点，再跳 2^(k-1) 层。两个半程拼成一个全程，倍增的名字也由此而来。

> ✅ 递推公式之所以成立：先跳到 up[u][k-1]（走了 2^(k-1) 层），再从那里跳 2^(k-1) 层。总共正好是 2^(k-1) + 2^(k-1) = 2^k 层。

### 🤔 为什么查询时要从大到小试探？

> ⚠️ 倍增查询的「一起跳」阶段，规则是：up[u][k] ≠ up[v][k] 才跳。为什么不能相等就跳？因为若 up[u][k] == up[v][k]，这个公共祖先可能就是 LCA，也可能在 LCA 之上。跳过去就可能越过答案，所以宁可不跳，最后用 up[u][0] 一步到位。这就是「试探」的意思。

---

## 倍增预处理：BFS + up 表逐格构建

预处理做两件事：① BFS 求出每个节点的深度和父节点（up[u][0]）；② 用递推公式逐列填满 up 表。总复杂度 O(n log n)。

🧠 算法伪代码
```
预处理 bfs(u):
  depth[u] = depth[fa[u]] + 1 // ① 深度
  up[u][0] = fa[u] // ② 第一列
  for j = 1 .. LOG-1: // ③ 逐列递推
    up[u][j] = up[ up[u][j-1] ][j-1]
查询 lca(u, v):
  if depth[u] < depth[v]: swap(u, v)
  for j = LOG-1 .. 0: // ④ 对齐（二进制）
    if depth[u] - 2^j ≥ depth[v]: u = up[u][j]
  if u == v: return u
  for j = LOG-1 .. 0: // ⑤ 一起试探
    if up[u][j] ≠ up[v][j]: u = up[u][j]; v = up[v][j]
  return up[u][0]
```

#### 🗂️ up[u][j] 倍增表示例

| 节点 i | up[i][0] 2^0 层 | up[i][1] 2^1 层 | up[i][2] 2^2 层 | up[i][3] 2^3 层 |
|--------|-----------------|-----------------|-----------------|-----------------|
| 1 | 0 | 0 | 0 | 0 |
| 2 | 1 | 0 | 0 | 0 |
| 3 | 1 | 0 | 0 | 0 |
| 4 | 2 | 1 | 0 | 0 |
| 5 | 3 | 1 | 0 | 0 |
| 6 | 4 | 2 | 0 | 0 |
| 7 | 4 | 2 | 0 | 0 |
| 8 | 5 | 3 | 0 | 0 |
| 9 | 5 | 3 | 0 | 0 |
| 10 | 6 | 4 | 1 | 0 |
| 11 | 7 | 4 | 1 | 0 |
| 12 | 8 | 5 | 1 | 0 |
| 13 | 8 | 5 | 1 | 0 |
| 14 | 10 | 6 | 2 | 0 |
| 15 | 10 | 6 | 2 | 0 |
| 16 | 14 | 10 | 4 | 0 |
| 17 | 14 | 10 | 4 | 0 |

> 💡 第一列是 BFS 顺带填的，后面的列才是递推公式发挥作用的地方。填完整张表只需要 O(n log n) 次计算。

---

## 倍增查询：二进制对齐 + 试探跳跃

查询分三步：① 保证 u 更深（不够就 swap）；② 深度对齐，用二进制分解把 u 跳到与 v 同深；③ 一起试探，从大到小尝试 2^k 层，up 值不同才跳；最后 up[u][0] 一步到 LCA。

🧠 算法伪代码
```
查询 lca(u, v):
  if depth[u] < depth[v]: swap(u, v) // 保证 u 更深
  d = depth[u] - depth[v] // 深度差
  for j = LOG-1 .. 0: // ④ 深度对齐（二进制）
    if (d >> j) & 1: u = up[u][j]
  if u == v: return u
  for j = LOG-1 .. 0: // ⑤ 一起试探跳跃
    if up[u][j] ≠ up[v][j]:
      u = up[u][j]; v = up[v][j]
  return up[u][0] // 一步到 LCA
```

### 🎯 边界案例

> 🎯 「祖先后代」：u 在 v 的祖先链上 → 深度对齐后 u == v，直接返回；「u == v」：深度差 0，零次跳跃；「同父兄弟」：一起跳阶段几乎全跳过，最后 up[u][0] 一步到位。都是高频边界，务必跑一遍。

---

## 复杂度分析：差距有多大？

n = 100,000 时：朴素最坏爬 100,000 层，倍增只需 ⌈log₂n⌉ = 17 跳。若查询次数 q = n：朴素总操作 ≈ 10,000,000,000，倍增 ≈ 1,700,000，快了约 5882×。

#### ⚖️ 全维度对比

| 维度 | 🧗 朴素 | 🚀 倍增 |
|------|---------|---------|
| 预处理 | 求深度（BFS/DFS） | 求深度 + 构建 up 表 |
| 预处理时间 | O(n) | O(n log n) |
| 预处理空间 | O(n) | O(n log n) |
| 单次查询 | O(n) | O(log n) |
| 代码难度 | ★☆☆☆☆ | ★★☆☆☆ |
| 适用场景 | 小树 / 教学理解 | 竞赛通用（n ≤ 10⁵ 量级） |

> ✅ 结论：预处理多花一点点（O(n log n) 的一次性投入），换来每次查询从 O(n) 降到 O(log n)。当查询次数 q 很大时，总复杂度从 O(nq) 变成 O(n log n + q log n)，差距会非常大。

## C++ 代码实现（模板）

完整可用的倍增 LCA 模板。直接复制即可在 OJ 上使用。

**lca.cpp · 倍增 LCA 模板**
```cpp
#include <bits/stdc++.h>
using namespace std;
const int N = 500010, LOG = 20;        // 2^20 > 1e5，LOG = ceil(log2 N)+1
vector<int> g[N];                       // 邻接表存树
int depth[N], up[N][LOG];               // 深度 & 倍增表
void dfs(int u, int fa) {               // 预处理：求深度 + 填 up 表
    up[u][0] = fa;                      // 跳 2^0=1 层 = 父节点
    for (int j = 1; j < LOG; j++)
        up[u][j] = up[up[u][j-1]][j-1]; // 倍增递推：两个半程拼全程
    for (int v : g[u]) if (v != fa) {
        depth[v] = depth[u] + 1;        // 子节点深度 = 父 + 1
        dfs(v, u);
    }
}
int lca(int u, int v) {
    if (depth[u] < depth[v]) swap(u, v);// 保证 u 更深
    int d = depth[u] - depth[v];        // 深度差
    for (int j = LOG-1; j >= 0; j--)    // 深度对齐：二进制拆分
        if (d >> j & 1) u = up[u][j];
    if (u == v) return u;               // 边界：u 就是 v 的祖先
    for (int j = LOG-1; j >= 0; j--)    // 一起试探跳跃（从大到小）
        if (up[u][j] != up[v][j]) u = up[u][j], v = up[v][j];
    return up[u][0];                    // 一步跳到 LCA
}
int main() {
    int n, m, s; cin >> n >> m >> s;
    for (int i = 1; i < n; i++) { int x, y; cin >> x >> y;
        g[x].push_back(y); g[y].push_back(x); }
    depth[s] = 0; dfs(s, 0);
    while (m--) { int u, v; cin >> u >> v; cout << lca(u, v) << '\n'; }
    return 0;
}
```

> ⚠️ 三个易错点：① LOG 取 `ceil(log2(n)) + 1`（n=10⁵ 时约 17+1）；② 从根 DFS 时要传 fa=0，并跳过父节点防止死循环；③ 查询时先 swap 保证 u 更深，再枚举二进制位。

### 🚀 变体：递归改 BFS 版

竞赛题经常「卡递归栈」（n = 10⁶ 的链会爆栈），此时改用 BFS/显式栈预处理。核心只有一句话：`up[u][j] = up[up[u][j-1]][j-1]` 与遍历顺序无关，先求出 depth 和 up[u][0] 即可。

**lca_bfs.cpp · 防爆栈版本**
```cpp
#include <bits/stdc++.h>
using namespace std;
const int N = 1000010, LOG = 21;
vector<int> g[N];
int depth[N], up[N][LOG];
queue<int> q;
void bfs(int root) {                     // BFS 版预处理（防爆栈）
    q.push(root); depth[root] = 0; up[root][0] = 0;
    while (!q.empty()) {
        int u = q.front(); q.pop();
        for (int j = 1; j < LOG; j++)
            up[u][j] = up[up[u][j-1]][j-1];   // 同一行递推
        for (int v : g[u]) if (v != up[u][0]) {
            depth[v] = depth[u] + 1;
            up[v][0] = u;
            q.push(v);
        }
    }
}
// lca 函数与 DFS 版完全相同，略
int main() { int n, m, s; cin >> n >> m >> s;
    /* 建图（略） */ bfs(s);
    while (m--) { int u, v; cin >> u >> v; cout << lca(u, v) << '\n'; }
    return 0;
}
```

## 应用与例题

LCA 是树上问题的地基。学会模板后，下面的经典应用都是「模板 + 一层推理」。

### 📐 应用一：树上两点距离

dist(u, v) = depth[u] + depth[v] − 2 × depth[ LCA(u, v) ]

> 💡 直觉：depth[u] + depth[v] 把两条到根的路径长度加起来了，其中 LCA 到根这段被重复计了两次，所以要减掉 2 × depth[LCA]。这是最常用的 LCA 应用（树上最短路径长度）。

### 🏔️ 应用二：树上路径最大值 / 最小值 / 边权和

把 up 表扩展成 mx[u][k]（从 u 向上 2^k 层路径上的最大值），递推时同步维护：`mx[u][k] = max(mx[u][k-1], mx[up[u][k-1]][k-1])`。查询 u→v 路径最值时，把路径拆成 u→LCA 和 v→LCA 两段，每段用二进制跳跃合并答案。「货车运输」等题就靠这个维护。

### 📝 例题精讲

**模板题 · 入门**

#### 【模板】最近公共祖先（LCA）

给定一棵 n 个节点的树（根为 1），q 次询问 LCA(u, v)。n, q ≤ 10⁵。

思路：直接套模板。注意本题 n 可达 10⁵，朴素 O(nq) 必 TLE（超时），正好用倍增来对比复杂度差距。

代码：使用上方模板，LOG 取 17（2¹⁷ = 131072 > 10⁵）。

**提高 · 货车运输类**

#### 树上路径最小边权 / 最大边权

n 个点的树，每条边有边权，q 次询问 u → v 路径上最小值。n, q ≤ 10⁵。

思路：维护 mn[u][k] = 从 u 向上 2^k 层路径上边权最小值。查询时把 u→v 路径拆成 u→lca、v→lca 两段，每一段从大到小跳并合并 mn 值。

递推：`mn[u][k] = min(mn[u][k-1], mn[up[u][k-1]][k-1])`。这就是「倍增 + 路径统计」的通用套路。

**经典 · 树上差分**

#### 路径加值 + 单点查询（树上差分）

给 u→v 路径上所有节点加 w，最后求每个点的值。n, q ≤ 10⁵。

思路：差分数组 cnt[]：`cnt[u]++, cnt[v]++, cnt[lca]--, cnt[fa[lca]]--`。全部操作后做一次树上前缀和（DFS 累加子树和），每个点的值就出来了。LCA 负责找到「分叉点」。

> 🎯 学习路径建议：先吃透「距离公式」的推导（纸笔画一遍），再做「路径最值」的 mn 表扩展，最后尝试树上差分。每一步都在复用倍增的「跳 2^k 合并信息」思想。
